Concept Definition

HTML 的狭义与广义

HTML 既可在狭义上指文本标记结构，也可在广义上指浏览器环境中的完整页面交付形态。

狭义 HTML：标记结构

指 `.html` 文件中的标记结构：标题、段落、列表、表格、链接、图片、表单。

  • 描述页面内容及其层级关系。
  • 支持 AI 对内容节点进行定位与修改。
  • 本质上属于可读、可检查的文本结构。

广义 HTML：页面成果

指浏览器可打开的完整页面：HTML 提供结构，CSS 控制外观，JavaScript 增加交互。

  • 承载用户最终可见与可操作的界面。
  • 支持浏览器即时渲染与验证。
  • 适合作为 AI 内容进入展示层的中间成果。

Format Positioning

HTML 在 AI 内容工作流中的中间层作用

不同格式对应不同工作阶段：Markdown 侧重内容组织，HTML 侧重页面呈现，PPT/PDF 侧重演示与分发。
机器可读性更强 视觉表达力更强 Markdown HTML PPT XML
XML：机器可读性高，但 AI 适配度有限
XML 标签严格、层级明确，适合程序校验与数据交换；但其语义通常依赖外部 schema、业务约定或文件规范，标签冗长且缺少直接呈现环境，因此不适合作为 AI 内容迭代的主要工作层。
PPT：视觉表达强，但机器可读性与 AI 适配性较弱
PPT 的信息大量嵌入文本框、坐标、图层、动画与母版关系中。AI 即使能读取文字，也难以稳定理解视觉顺序、强调层级和对象关系，因此后续修改成本较高。
HTML：处于结构可读与浏览器呈现之间
HTML 以标签表达内容关系，又能在浏览器中直接验证样式和交互，因而更适合作为 AI 内容生产中的中间层格式。

Concept Analysis I

HTML 的结构显式性

HTML 通过标签结构描述标题、段落、列表和区块，使内容关系从视觉推断转向语义标记。

结构显式性 是 HTML 区别于纯视觉排版的重要特征。

在 HTML 中，标题、段落、列表与章节均由明确标签承载，模型无需单纯依赖字号、坐标或图层进行推断。

因此，HTML 更适合作为 AI 进行局部修改、结构重排与内容复用的中间格式。

<main> 页面主体；用于区分核心内容与辅助信息。
<section> 主题分组；支持按主题拆分、增删与重排。
DOM 树 浏览器解析 HTML 后形成的文档对象结构，可用于检查整体层级。
<article>
  <h1>AI 时代为什么要重视 HTML</h1>
  <p>HTML 是内容进入浏览器界面的中间层。</p>
  <section>
    <h2>核心理由</h2>
    <ul>
      <li>结构清楚</li>
      <li>容易修改</li>
      <li>可以直接预览</li>
    </ul>
  </section>
</article>

07 / 22概念解析与格式定位
HAI Guidelines
Code Inspection

HTML 代码初步检查

初步检查的目标不是完整调试，而是快速判断结构、样式与行为分别位于何处，并确认浏览器能否正确加载。
SCENARIO A

HTML / CSS / JS 三者拆开

适用于正式项目、可维护页面或多人协作场景。检查重点是文件之间是否被正确引用。

  1. 先打开 `.html`，确认主体结构、标题、按钮、图片和容器是否存在。
  2. 检查 `<link rel="stylesheet">` 是否正确指向 `.css` 文件。
  3. 检查 `<script src="...">` 是否正确指向 `.js` 文件。
  4. 打开浏览器控制台，查看资源加载、路径错误和脚本报错。
判断顺序：结构是否存在 → 样式是否生效 → 行为是否触发。
SCENARIO B

HTML / CSS / JS 写在同一文件

适用于单文件演示、快速原型或 AI 生成页面。检查重点是三层代码是否被放入正确区域。

  1. 先看主体标签：`<section>`、`<div>`、`<button>` 是否构成清晰结构。
  2. 再找 `<style>` 区域，确认选择器能对应到 HTML 中的 `class` 或 `id`。
  3. 最后找 `<script>` 区域，确认事件监听、函数名和元素 `id` 是否一致。
  4. 在浏览器中逐项点击，验证状态切换、上传、播放或复制等交互是否可用。
检查元素通常优先显示 DOM 结构，因此会先看到 `body / main / div`；若要完整查看 `style` 与 `script`，应使用“查看源代码”或 DevTools 的 Sources 面板。

10 / 22概念解析与格式定位
HAI Guidelines
Prompt Constraint

HTML 生成中的结构约束原则

在 AI 生成 HTML 时，应优先约束内容结构、页面模块与输出边界，再进入视觉样式和交互设计。
低约束输入：
“生成一个视觉效果较好的网页。”

结构化输入：
请生成一个单文件 HTML 页面：
1. 主题：AI 时代的 HTML 文件格式指南
2. 受众：非前端背景的科研与内容生产者
3. 结构：前言、格式定位、概念解析、工作流程、应用边界
4. 要求：每个 section 对应一个概念或流程单元
5. 结构确认后，再补充 CSS 表现层与少量 JavaScript 行为层

原则：低约束输入容易使模型优先生成视觉装饰；结构化输入有助于稳定页面层级与内容边界。

在结构明确后，再追加表现层和行为层，能够降低后续重构成本。

HAI Guidelines
Boundary Condition

HTML 工作流的复杂度边界

HTML 并非天然降低复杂度；当结构、样式与脚本缺乏分层约束时，页面同样会出现维护困难。

当 HTML 内部混入大量内联样式、重复组件与长脚本时，其可读性与可维护性会显著下降。

约束原则：HTML 负责结构，CSS 负责表现，JavaScript 负责必要行为，避免三层职责混写。

HTML 的优势在于可被分层控制，而非自动生成高质量结构。

选择

本地文件进入页面

点击占位框触发文件选择，不需要后端上传，即可在当前浏览器会话中读取媒体。

预览

即时替换占位状态

说明

结构仍需保留语义

边界

预览不等于发布

本地选择只在当前页面临时生效；正式分享仍需将媒体文件放入项目目录并使用相对路径。

Boundary & Scope

常见误解与 HTML 优先适用场景

HTML 的价值应放在具体工作阶段中理解：先排除替代性叙事，再判断其优先适用的内容任务。

误解一：HTML 等同于网页设计。

HTML 首先承担结构化表达功能，视觉设计应在结构稳定后由 CSS 与组件系统逐步补充。

误解二：HTML 可以替换掉 MD 和 PPT。

这是常见的噱头和误区。Markdown 更适合原稿组织，PPT 更适合现场表达；HTML 的优势在于中间层呈现、交互验证与跨格式衔接。

报告页面

在线报告、课程讲义

需要浏览器直接打开，并且比 Markdown 更有视觉组织。

交互 Demo

小工具、仪表盘、模拟器

需要点击、筛选、动画、数据变化，不只是静态页面。

AI 协作

可迭代的可视化成果

支持 AI 修改局部结构、样式和脚本，降低重复制图与重排成本。

跨格式输出

转 PDF、截图、PPT 素材

HTML 可作为发布前的统一预览层，再导出到其他格式。

以 HTML 为最终产品的 Web 端 Vibe Coding 流程

当目标是可查询、可筛选、可交互的在线工具时，HTML 不再只是中间层，而可以成为最终交付形态。
需求与数据输入县级分区数据、行政区划边界、字段口径与交互目标。
AI 辅助生成页面骨架形成 `index.html / styles.css / app.js` 的基本结构。
浏览器内持续迭代通过搜索、筛选、地图点击、缩放、导出等行为验证真实使用场景。
HTML 作为最终产品交付一个可打开、可部署、可继续修改的 Web 端小工具，而非静态截图或单页汇报。
优势：HTML 将内容、数据、界面与交互放在同一可验证环境中，适合 Web 端 vibe coding 的快速试错与持续修正。

Publication

HTML 发布方式

HTML 成果的交付不止于“打开一个文件”，还包括资源打包、静态托管、服务器部署与版本维护等不同层级。
01 LOCAL FILE

本地打开

直接通过浏览器打开 `.html` 文件，适合课堂演示、个人预览和离线展示。

  • 注意图片、视频、脚本路径是否可访问。
02 PACKAGE

文件夹打包

将 HTML、CSS、JS、图片、视频和数据文件放入同一目录结构后整体分享。

  • 优先使用相对路径，减少跨电脑失效。
03 STATIC HOSTING

静态托管

发布到 GitHub Pages、学校服务器或静态网站平台，形成可访问链接。

  • 适合报告页面、课程讲义和展示型工具。
04 WEB APP

服务器部署

当页面需要接口、数据库、权限或多人协作时，HTML 进入完整 Web 应用体系。

  • 需要同时管理前端、后端与数据安全。
